## Layering migration backlog (ADR 0004) — ✅ COMPLETE (2026-06-05)

All 19 controllers + 9 application services + 6 CQRS handlers + 16 Infrastructure
services have been migrated to `IUnitOfWork` + `IRepository<T>` / `IReadOnlyRepository<T>`
per [docs/ADR/0004-controller-service-repository.md](ADR/0004-controller-service-repository.md).
A CI grep gate ([.github/workflows/ci.yml](../.github/workflows/ci.yml)) fails the
build if any new `IAppDbContext` field declaration sneaks into the Controllers
or Application layers.

The only files that still reference `IAppDbContext` are the seam itself
(`UnitOfWork`, `GenericRepository`, `TransactionBehavior`), the bootstrap seed
classes, and two background-worker / pre-tenant-resolution callers
(`ReportSchedulerBackgroundService`, `ApiKeyAuthorizer`). Each is intentional
and documented in the 2026-06-05 implementation-log entry.

### CrossCutting concerns — where each lives

cc24 conventionally has a separate `CrossCutting` project. In this codebase
the equivalent concerns are organised by lifetime + dependency direction
rather than by a single label, distributed across the platform layers:

| Concern | Location |
|---|---|
| Logging | `Platform.Presentation.Observability` (Serilog wiring); ILogger<T> everywhere |
| Distributed tracing + metrics | `Platform.Presentation.Observability.TelemetryExtensions` (OpenTelemetry) |
| Exception handling | `Platform.Presentation.Middleware.GlobalExceptionMiddleware` (RFC 7807) |
| Caching | `Platform.Application.Abstractions.Caching.ICacheService` + `Platform.Infrastructure.Caching.CacheService` (L1+L2) |
| Output caching | `Program.cs` `AddOutputCache` with named policies |
| Audit trail | `Platform.Application.Abstractions.Audit.IAuditTrail` + `Platform.Infrastructure.Audit.AuditTrail` |
| Tenancy | `Platform.Application.Abstractions.Tenancy.ITenantContext` + `TenantContextMiddleware` |
| Security headers + CSP nonces | `Platform.Presentation.Middleware.SecurityHeadersMiddleware` + `Security/CspNonceTagHelper` |
| Authn / Authz | `Platform.Presentation.Auth.PlatformAuthExtensions` (Cookie + JWT + ApiKey multiplexer) |
| Rate limiting | `Program.cs` `AddRateLimiter` |
| Validation | `Platform.Application.Dispatch.ValidationBehavior` pipeline behaviour |
| Background jobs | `Platform.Infrastructure.BackgroundJobs` + `CanteenManagementSystem.Infrastructure.BackgroundJobs` |
| Real-time | `Platform.Application.Abstractions.RealTime.IOrderBroadcaster` + `SignalROrderBroadcaster` |

Splitting these into a single `Platform.CrossCutting` project would force
all eight concerns onto one lifetime and would push ASP.NET Core types
into the platform middle layers. The current layout keeps the
dependency direction strict (Domain ← Application ← Infrastructure ←
Presentation) while still letting any product compose the
cross-cutting concerns it needs in one line per concern.
